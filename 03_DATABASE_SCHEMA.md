# 03_DATABASE_SCHEMA.md

> **This document is the authoritative source of truth for all persisted data, schema relationships, and runtime model contracts for Absürt Mahkeme. No database object, table, column, or persistent field may be created, renamed, or removed without being updated here first.**

---

## Storage Model Summary

- **Engine:** PostgreSQL (Supabase Postgres)
- **Access style:** Drizzle ORM (`pg` driver, TypeScript), all schema in `packages/db`
- **Canonical schema format:** Drizzle TypeScript schema; all DDL/migrations are generated from these declarations
- **Primary key strategy:** UUID (`uuid`) required for every PK (generated by app/server or DB; schema examples use Drizzle `defaultRandom()`). Room codes are unique 6-char uppercase alphanumeric (`[A-Z0-9]{6}`), enforced unique per room
- **Timestamp strategy:** UTC `timestamptz`, with `created_at` (all), `updated_at` (where mutable), `started_at`, `ended_at` (for lifecycle entities)
- **Delete strategy:** Hard delete only (no soft delete in MVP)
- **Naming convention:** All table/column names in `snake_case`. All enum/text values in `lowercase_snake_case`
- **Seed/bootstrap strategy:** TypeScript script `packages/db/scripts/seed.ts` (`pnpm db:seed`)

## Global Data Conventions

- **PKs:** UUID (`uuid`), generated by app/server or DB
- **Room codes:** `varchar(6)`, unique, strictly uppercase `[A-Z0-9]{6}`
- **Timestamps:** Always UTC, `timestamptz(6)`
- **Foreign Keys:** All FKs as `uuid`, `onDelete: 'CASCADE'`
- **Enums:** Use `varchar` with DB-level `.check()` or Postgres enum; only allowed values
- **JSON fields:** Only `jsonb`, well-structured; not for unchecked user input
- **Indexing:** All PKs, FKs, room code, and unique constraints at DB level
- **Audit:** All tables at least `created_at`; `updated_at` if updatable
- **Seed Data:** All curated data in seed script, not in application code
- **Text fields:** All user input validated and filtered before DB insert

### Object: `rooms`
**Purpose:** Represents all game rooms—active, waiting, or closed.

#### Canonical Schema Definition
```ts
import { pgTable, uuid, varchar, integer, timestamp } from 'drizzle-orm/pg-core';
export const rooms = pgTable('rooms', {
  id: uuid('id').primaryKey().defaultRandom().notNull(),
  code: varchar('code', { length: 6 }).notNull().unique(),
  status: varchar('status', { length: 24 }).notNull().default('waiting'),
  max_participants: integer('max_participants').notNull().default(8),
  created_at: timestamp('created_at', { mode: 'date', precision: 6 }).notNull().defaultNow(),
  updated_at: timestamp('updated_at', { mode: 'date', precision: 6 }).notNull().defaultNow(),
  closed_at: timestamp('closed_at', { mode: 'date', precision: 6 })
});
```

#### Application Representation
```ts
export type Room = {
  id: string;
  code: string;
  status: 'waiting' | 'active' | 'closed';
  max_participants: number;
  created_at: Date;
  updated_at: Date;
  closed_at: Date | null;
};
```

#### Field Reference

| Field            | Type        | Nullable | Default   | Indexed | Description                      |
|------------------|------------|----------|-----------|---------|----------------------------------|
| id               | uuid       | false    | auto      | yes     | PK                               |
| code             | varchar(6) | false    |           | unique  | 6-character, unique              |
| status           | varchar(24)| false    | waiting   | no      | 'waiting'/'active'/'closed' enum |
| max_participants | integer    | false    | 8         | no      | 2 players + up to 6 jury/spectat.|
| created_at       | timestamptz| false    | now()     | no      | Creation UTC timestamp           |
| updated_at       | timestamptz| false    | now()     | no      | Last update                      |
| closed_at        | timestamptz| true     | null      | no      | Null unless closed               |

#### Relationships & Integrity Rules
- PK: `id`, unique: `code`
- Delete room: cascades to participants, rounds, etc.

### Object: `room_participants`
**Purpose:** Tracks all individuals ever joined to a room.

#### Canonical Schema Definition
```ts
import { pgTable, uuid, varchar, timestamp, integer, uniqueIndex, index } from 'drizzle-orm/pg-core';

export const room_participants = pgTable('room_participants', {
  id: uuid('id').primaryKey().defaultRandom().notNull(),
  room_id: uuid('room_id').notNull().references(() => rooms.id, { onDelete: 'CASCADE' }),
  nickname: varchar('nickname', { length: 18 }).notNull(),
  role: varchar('role', { length: 24 }).notNull().check(
    'role_check',
    "role IN ('davaci', 'davali', 'jury', 'spectator')"
  ),
  joined_at: timestamp('joined_at', { mode: 'date', precision: 6 }).notNull().defaultNow(),
  left_at: timestamp('left_at', { mode: 'date', precision: 6 }),
  session_token: varchar('session_token', { length: 40 }).notNull(),
  is_active: integer('is_active').notNull().default(1)
},
(room_participants) => ({
  roomIdNicknameUnique: uniqueIndex('room_participants_room_id_nickname_unique').on(room_participants.room_id, room_participants.nickname),
  sessionTokenUnique: uniqueIndex('room_participants_session_token_unique').on(room_participants.session_token),
  nicknameIdx: index('room_participants_nickname_idx').on(room_participants.nickname)
}));
```

#### Application Representation
```ts
export type RoomParticipant = {
  id: string;
  room_id: string;
  nickname: string;
  role: 'davaci' | 'davali' | 'jury' | 'spectator';
  joined_at: Date;
  left_at: Date | null;
  session_token: string;
  is_active: 0 | 1;
};
```

#### Field Reference

| Field         | Type     | Nullable | Default | Indexed           | Description                          |
|---------------|----------|----------|---------|-------------------|--------------------------------------|
| id            | uuid     | false    | auto    | yes               | PK                                   |
| room_id       | uuid     | false    |         | yes (FK)          | Parent room                          |
| nickname      | varchar  | false    |         | unique composite  | Unique per room                      |
| role          | varchar  | false    |         | no                | 'davaci','davali','jury','spectator' |
| joined_at     | timestamptz| false  | now     | no                | When joined                          |
| left_at       | timestamptz| true   | null    | no                | Leave timestamp                      |
| session_token | varchar  | false    |         | unique            | Signed token, unique                 |
| is_active     | integer  | false    | 1       | no                | 1=present, 0=left                    |

#### Relationships & Integrity Rules
- Unique: (`room_id`, `nickname`)
- Unique: `session_token`
- Allowed roles enforced by CHECK constraint
- Cascade on room delete

#### Field Reference

| Field             | Type     | Nullable | Default | Indexed         | Description                                |
|-------------------|----------|----------|---------|----------------|--------------------------------------------|
| id                | uuid     | false    | auto    | yes            | PK                                         |
| room_id           | uuid     | false    |         | yes (FK)       | Parent room                                |
| round_index       | integer  | false    |         | unique composite | Sequence/ordering within room             |

#### Relationships & Integrity Rules
- Unique: (`room_id`, `round_index`)
- On room delete, cascades to all this room's rounds

## Migration Strategy

- **Tool:** Drizzle Kit (`pnpm db:migrate`), migrations in `packages/db/migrations`
- **File naming:** `YYYYMMDDHHmmss_descriptive.sql` (e.g. `20240527122331_add_jury_votes.sql`)
- **Change policy:** ALL schema changes appear here first. After doc update, use Drizzle to generate and run DB migration.
- **Rollback policy:** Each migration must contain a valid down/revert path. All migrations must be reversible with `drizzle-kit down`.
- **CI/release behavior:** Schema drift in CI fails the build; migrations run automatically in deploy pipelines.
- **Branching expectations:** All new work is rebased on latest migrations in `main` before merge; schema changes in parallel branches require manual migration/test merge before release.

---

> **NOTE:**  
> All migrations and model changes in the codebase, as well as every query and type, must exactly mirror and reference this spec. Session tokens, nickname+room and round-index composite uniqueness, and enum/correctness guarantees are **enforced at DB-level** and must never rely on app-only checks.
